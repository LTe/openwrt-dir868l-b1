# v0.3.1 validation

Tested on a physical DIR-868L B1 with OpenWrt r37659 / Linux 6.18.55 and a
GL-MT6000 client. The module was taken from the locally built
`kmod-brcm-wl-blob-6.18.55-r4.apk` package, rather than the separate prototype
build. Firmware publication uses the clean GitHub Actions image build.

Tested module SHA256:

```
37cf8e9e403f9e5466e058a3e7ceed21794d62b60c3118adb7e3b05ed60fd505
```

## Changes validated

The FreshTomato package enables hardware IPv4 TCP TX checksums on BCM4360,
RX/TX batching, selective TCP GRO, forwarding-aware GRO selection, and TX
headroom expansion using private skb structures. Unsupported checksum cases
fall back to software. All-protocol GRO and the A-MSDU header pool remain off.

The package and the alternate D-Link-core variant both compile. The alternate
variant is a build-only compatibility check; its performance was not retested.
Glue, OSL, checksum-header/cache and checksum-eligibility selftests pass on
both radio probes. The new UCI `amsdu` setting was exercised at both `0` and
`1`, verifying the value reported by the radio after netifd setup. Testing a
new shell-driver attribute requires restarting netifd, which caches its schema.

## Short TCP streams and socket ownership

Release testing found a failure absent from the earlier bulk transfers. With
A-MSDU and the combined optimizations enabled, 4096 records of 8 bytes could
stop after only 1332 or 1662 received records. Every captured packet had valid
checksums. Disabling individual optimizations avoided the observed stalls,
but did not establish a checksum error.

The modern port retained socket ownership on packets queued by the legacy
core. Linux 2.6.36 called `skb_orphan_try()` before the driver's transmit entry.
The integration now explicitly releases ownership before the core can retain
a packet for aggregation, including packets that need no headroom expansion.
Shared skb structures are copied first. Releasing ownership only on expansion
was insufficient: its counter stayed at zero during a failing short transfer.

The final module passes record sizes 8, 33, 1400 and 65507 with A-MSDU both
enabled and disabled. Receiver GRO was disabled only during capture to avoid
checking synthetic GRO packets. Three final-module captures checked 14,504,
11,182 and 13,259 TCP packets respectively: zero bad IP checksums, bad TCP
checksums or truncated frames. TCP records were complete and their payloads
and sequence numbers matched. All optimizations remained enabled.

and CPU trial, counters, retransmissions, module hash and capture summaries.
Throughput entries in the README are means of two 12-second runs. Both radios
used WPA2-CCMP, TX A-MSDU disabled and A-MPDU enabled.

| 5 GHz VHT80 | 1 | 320.89 Mbit/s | 256.44 Mbit/s | 4 / 0 |

Retransmit counts are totals over both runs, not rates. Saturated multi-stream
tests are not lossless-link demonstrations.

The CPU comparisons toggle `rx_batch`, `tx_batch`, `rx_tcp_gro`,
`rx_tcp_gro_local_data`, `tx_expand` and `cso_stack` together. `cso_offload=1`
keeps the same descriptor format in both settings; TX socket ownership release
also stays enabled in both. The order is off/on/on/off, 12 seconds per direction.

The Wi-Fi-to-Ethernet bridge comparison does not show a CPU gain. The local RX,
local TX and Ethernet-to-Wi-Fi comparisons do show lower CPU at similar rates.
These measured effects should not be added to earlier isolated percentages.

On the final module, the 5 GHz A-MSDU-on suite passed TCP (512 x 65,507 bytes),
UDP (50,000 x 1400 bytes at 100 Mbit/s) and fragmented UDP (128 x 65,507 bytes
at 15 Mbit/s), all in both directions. Final bridged A-MSDU-off checks passed
the same TCP count, 50,000 x 1400-byte UDP at 50 Mbit/s and individually paced
128 x 65,507-byte UDP at 15 Mbit/s, again in both directions. No payload,
sequence, duplicate or missing-record errors were reported in those suites.

Final IPv6 TCP checks passed 2048 x 65,507-byte records in each direction.
The previous neighbor-discovery timeout was resolved by a temporary rule
allowing neighbor solicitation/advertisement on the client's test interface;
the rule was removed afterward. IPv6 UDP passed on the earlier integrated
build before the TX socket-ownership correction; it was not repeated afterward.

## Scope and limits

Wi-Fi endpoint measurements bypass the 100 Mbit/s switch in the wired path;
iperf runs on the router, so endpoint CPU includes iperf's cost. Bridged tests
use 80 Mbit/s below that wired limit and measure CPU efficiency, not maximum
bridge or NAT throughput. Radio conditions can vary between short trials.

An early integrated-build bridge trial lost 6 of 50,000 UDP datagrams; a
subsequent off/on/on/off comparison delivered all 400,000 datagrams. A 2.4 GHz
trial on the final module lost 2 of 50,000 UDP datagrams at 20 Mbit/s. No bad
payloads, checksum errors or new kernel error messages accompanied these
losses. A follow-up 2.4 GHz control lost 8 of 20,000 upload datagrams with
the packet optimizations disabled; the enabled trial delivered all 20,000
in each direction. Fragmented UDP (128 x 65,507 bytes at 10 Mbit/s) passed
both directions on 2.4 GHz. These observations do not establish a cause or universally lossless
UDP operation. Payload tests use enlarged receive buffers; small application
buffers have separate, previously recorded overflow limitations.

Forced Wi-Fi fragmentation with A-MPDU disabled remains a pre-existing
unresolved boundary. TSO is not enabled. These are short functional and
performance tests, not a long-duration stability qualification.
