## Changes in v0.3.1

- Integrated BCM4360 hardware IPv4 TCP transmit checksums into the packaged driver.
  Unsupported packets use software checksums; TSO is not enabled.
- Enabled TCP receive GRO with a forwarding-aware selector: bridged TCP data bypasses
  GRO when it would otherwise need segmentation again on Ethernet output. UDP keeps
  the regular receive path.
- Enabled RX/TX batching and reuse of private linear TX packet buffers when extra
  headroom is needed. Small packets retain the original allocation path.
- Restored release of TX socket ownership before the legacy core's aggregation
  queues, preventing short TCP streams from stalling with the combined optimizations.
- Added the optional per-radio UCI setting `amsdu`. Setting it to `0` can reduce CPU
  work on strong-signal links while leaving A-MPDU enabled.
- Added checksum eligibility and cached-header selftests. The alternate D-Link core
  keeps its previous defaults and does not use the FreshTomato checksum hooks.

The packet optimizations above are enabled by default for the FreshTomato core.
All-protocol GRO and the experimental A-MSDU header pool remain disabled by default.

See the [README performance tables](https://github.com/LTe/openwrt-dir868l-b1/blob/v0.3.1/README.md)
and [validation report](https://github.com/LTe/openwrt-dir868l-b1/blob/v0.3.1/docs/releases/v0.3.1-validation.md)
for measurements and test scope. Forced Wi-Fi fragmentation with A-MPDU disabled remains an
unresolved pre-existing driver limitation.
